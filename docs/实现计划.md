# 本体智能平台第一版实现计划（历史基线）

> 本文自 2026-08-29 起不再是当前执行权威，仅用于解释存量 `legacy` Agent 和旧界面的设计来源。当前架构、任务状态和验收标准以 [平台能力化优化升级任务计划](./优化升级任务计划文档.md) 为准。任何“必须有数据源/映射/固定 Agent 数据绑定”的描述只适用于 legacy 兼容模式，不得用于新能力链路。

## 1. 第一版目标

平台只解决一件事：把任意行业的一个业务场景，建设成 Agent 能够准确理解、查询、计算、判断和执行的业务语义空间。

唯一主链路为：

```text
创建业务场景
  → 建立本体骨架（对象类型 / 属性 / 关系类型）
  → 接入并测试数据源
  → 配置数据映射（形成对象实例 / 关系实例）
  → 配置函数 / 操作 / 规则 / 事件 / 工作流
  → 创建并检查 Agent
  → 在对话中完成业务需求
```

平台不再区分“运营”和“构建”。同一个用户围绕同一个业务场景完成建设、验证和使用。

## 2. 信息架构

### 2.1 一级导航

- 核心流程：业务场景、数据源、Agent。
- 运行：任务中心，用于工作流状态、重试和人工审批。
- 系统设置：模型、本地技能、外部工具服务，统一收纳在“能力配置”中。

场景内部使用固定标签：本体模型、实例数据、数据映射、函数、操作、规则、事件、工作流。

不得新增与这条链路重复的“工作台”“中心”“驾驶舱”或另一套模式导航。新增页面前必须说明它解决主链路中的哪个不可替代问题；无法说明则不新增。

### 2.2 已删除的产品面

以下能力不属于第一版独立产品面，前端页面和菜单已经删除：

- Dashboard
- 高级数据与模型
- 连接器与环境
- 端到端血缘
- 异常中心
- 权限中心
- 发布中心
- 资源包与 Starter Kit
- Operator / Builder 切换
- 闭环工作台和五阶段顶部轨道

权限检查、定义快照、连接解析和执行审计仍可作为内部安全机制存在，但不得要求普通用户理解其内部 ID、哈希、环境绑定或发布术语。

## 3. 本体模型边界

第一版采用业界通用、接近 Palantir Ontology 语义的名称，不创造同义新词：

- 对象类型（Object Type）：业务对象的类型定义。
- 属性（Property）：对象的类型化字段，包含主键、必填、唯一、枚举、格式、范围等约束。
- 关系类型（Link Type）：两个对象类型之间带方向和基数的语义关系。
- 对象实例（Object Instance）：由人工创建或数据映射形成的真实业务对象。
- 关系实例（Link Instance）：真实对象之间的关联。
- 操作（Action）：可能写入数据或调用外部系统的受控能力，必须支持预演、权限检查和明确确认。
- 函数（Function）：无外部副作用的确定性计算，可由 Agent 直接调用。

当前模型还应保留：命名空间、抽象对象类型、属性描述、生命周期状态属性、来源信息、有效时间和质量状态。

第一版不宣称复制 Palantir 的全部企业能力。继承接口、复杂单位系统、语义版本编辑器、大规模增量图计算等，应在真实业务场景证明必要后再进入后续版本。

## 4. 数据源与映射顺序

标准顺序是“本体骨架 → 数据源 → 映射”，原因如下：

1. 先用业务语言确定对象、属性和关系，避免让数据库表结构反向决定业务语义。
2. 再接入数据源并读取真实表、列或文档结构。
3. 最后把真实字段映射到对象属性，预览、测试并刷新为实例。

没有本体对象类型时不能创建映射；没有可用数据源时也不能创建映射。界面应直接说明缺少哪一步，并提供前往对应页面的按钮。

映射必须使用“对象属性 ← 数据列”的逐字段选择。转换规则使用可选择、可排序的安全步骤，不允许用户提交任意脚本。

## 5. 业务能力

### 函数

- 用于评分、阈值判断、距离计算、时序聚合等确定性计算。
- 输入和输出使用字段表配置，不要求手写数据结构。
- 只有选择可运行计算方式的函数才会暴露给 Agent；“仅定义”函数只用于梳理需求。

### 操作

- 用于查询或写入数据、调用受控本地技能、外部工具或 HTTPS 服务。
- 输入参数使用字段表；普通配置使用结构化表单。
- 真实执行前先预演，并使用防重复提交标识；有副作用时要求用户确认或审批。

### 规则、事件和工作流

- 规则使用条件构建器配置字段、比较方式和值。
- 事件使用字段表定义携带的数据，并可触发已启用工作流。
- 工作流使用可视化节点和连线编辑器；节点参数使用对应表单。
- 任务中心只呈现业务状态、输入、结果、重试和审批，不展示底层快照 ID 或校验哈希。

## 6. Agent 就绪条件

Agent 可以先保存为草稿，但只有满足以下条件才开放对话：

1. 已绑定业务场景。
2. 场景至少有一个对象类型。
3. 场景已有可用数据源。
4. 至少有一条有效数据映射。
5. 已配置可用对话模型。
6. Agent 已绑定映射所使用的数据源。

界面必须逐项显示缺失条件，并把用户带回“本体模型 / 数据源 / 数据映射 / Agent 配置”中的准确位置。

Agent 的可调用能力至少包括：对象与实例查询、数据库查询、文档检索、确定性函数、规则评估、操作预演和工作流协作。操作产生真实副作用时不得由聊天文本直接绕过确认。

## 7. AI 文档建模

人工整理的行业文档进入本体建模时，执行以下流程：

1. 完整读取附件；超过明确上限时直接报错，不静默截断。
2. 先识别对象类型、属性、约束、关系类型、规则、事件和工作流候选。
3. 保存来源片段和识别依据。
4. 生成结构化变更清单，展示新增、修改、跳过和冲突。
5. 用户确认后才写入正式场景。
6. 应用后执行结构校验，并报告未识别、歧义和冲突项。

“生成本体”请求必须优先进入本体提取，不能因为文档偶然出现“字段、表、映射”等词就错误路由为数据映射。临时附件不会自动成为正式数据源。

当前已实现完整业务模型编译器：同一次请求可从用户业务描述和临时附件生成对象、属性、关系、函数、操作、规则、事件、工作流、对象映射和关系映射，并形成一份相互引用的复合变更清单。系统逐段记录 coverage 与 evidence，冲突、歧义、缺失引用或非法约束会阻止应用；用户确认后才在同一事务中原子写入，任一环节失败都会整体回滚。长文档采用有预算的分块编译与可恢复任务，不会静默截断或断线后自动重提。

场景内 AI 助手提供明确的“完整场景建模”入口，也支持本体、映射、业务能力和工作流等聚焦任务。AI 生成的操作仍保持待绑定和停用，规则、事件、工作流保持停用或草稿；真实副作用必须继续经过平台的权限检查、预演和显式确认，不能把“AI 可建设定义”误解为“聊天可绕过治理直接执行”。

下一优先级是扩充多行业黄金样本集，按对象、属性、关系、约束、函数、操作、规则、事件、流程、映射和来源分别计算准确率与召回率；仅凭“模型返回成功”不能视为精准建模。同时逐步补齐已有业务能力的受控更新/删除、实例操作和映射刷新等 authoring tools。

## 8. 表单与展示原则

- 普通用户不手写或直接阅读 JSON。
- 对象配置使用属性表、枚举编辑、关系选择和约束控件。
- 函数、操作和事件使用输入/输出字段构建器。
- 规则使用条件构建器。
- 任意嵌套参数和执行结果使用树状结构编辑器或结构化查看器。
- 原始文本只用于文档原文、引用证据或命令输出等确实需要保真的场景。
- 内部英文枚举值、环境名、哈希和实现 ID 不直接作为主界面文案。

## 9. 第一版验收标准

- 导航中不存在运营/构建切换和已删除产品面。
- 用户能创建场景并使用标准术语完成对象类型、属性、关系类型和实例建模。
- 映射在缺少对象类型或数据源时明确阻止，并能引导修复。
- 函数、操作、规则、事件和工作流均可用结构化界面配置。
- Agent 未就绪时不能进入对话；就绪后能发现并调用场景函数和其他受控能力。
- 长文档不会静默截断；AI 本体草稿和变更清单可检查、可追溯、确认后应用。
- 主要页面在桌面、深色主题和 375px 宽度下无横向溢出、遮挡或不可达操作。
- 前端生产构建、后端全量测试和关键浏览器流程全部通过。

## 10. 当前实现记录（2026-08-22）

- 已将前端收敛为单一导航和单一场景工作流。
- 已物理删除高级资产、异常、血缘、资源包、Starter Kit 等前后端独立模块及其测试。
- 已把函数运行时接入 Agent 工具发现与调用。
- 已补齐关系实例的结构化创建、查看和删除，实例建模不再只有对象实例。
- 已把主要 JSON 输入和 JSON 结果展示替换为结构化组件。
- 已修复 AI 本体意图路由、长附件与工作流输入静默截断、已有对象属性被整项跳过、关系指向已有对象时被过滤，以及 AI 工作流跨场景或缺失引用可落库的问题。
- 后端仍保留权限、定义快照和连接解析内核，用于安全执行；它们不是第一版独立菜单。

## 11. 增量实现记录（2026-08-24）

- 场景 AI 助手已公开完整业务模型、本体、映射、业务能力聚焦引导、工作流、只读解释和操作预演等任务入口；复合自然语言请求会进入完整编译器。
- 普通问答上下文已补充经过属性与资源权限过滤的无密钥摘要，覆盖函数、操作、规则、事件、工作流、可见数据源和映射；复合提案可按资源查看摘要、置信度与来源段落。
- MCP 页面支持常见客户端 `mcpServers` JSON 的预检与原子导入，兼容 `type=http`、SSE 和由运维显式开启的 stdio，并支持请求头的写入、脱敏编辑与显式删除。
- Streamable HTTP 已按当前 MCP Python SDK 使用注入的 HTTP client 传递认证头；连接失败不再被界面误报为成功。
