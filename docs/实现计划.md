# 本体智能平台实现计划

## 1. 建设目标

将当前的“业务场景 + Agent + 工具调用”原型，升级为以本体为核心的业务决策与执行平台。

核心关系：

```text
业务场景（目标、角色、边界）
        ↓
本体资源包（对象、关系、状态、规则、动作、事件、权限）
        ↓
数据与逻辑（数据库、文档、模型、函数、工作流）
        ↓
AI 助手 / Agent / 业务应用
        ↓
经过权限与审批后执行动作，并记录完整决策链路
```

基本原则：大模型负责理解、规划和解释；本体负责表达业务事实和能力；工作流与 Action 负责可靠执行；安全策略贯穿所有环节。

## 2. 目标平台结构

- 体验层：业务工作台、对象浏览、任务中心、运营应用、全局 AI 助手。
- AI 层：Agent、模型路由、知识检索、工具调用、记忆、评测和可观测性。
- 本体运行时：对象类型、关系类型、属性、状态、事件、规则、函数、Action。
- 数据与逻辑层：数据库、API、文件、消息流、Embedding、业务模型和工作流。
- 治理层：租户、角色、对象/属性权限、审计、血缘、版本、审批和发布。

本体资源应统一组织为可版本化的“本体资源包”：

```text
对象类型 / 关系类型 / 属性约束
数据映射 / 规则 / 函数 / Action
事件 / 工作流 / 权限策略 / 测试用例
版本 / 血缘 / 审计记录
```

## 3. 分阶段实现路线

### P0：形成可用闭环

目标：让用户能够从业务描述开始，完成“建模—映射—查询—动作—审计”的完整流程。

- 扩展本体模型：命名空间、类型约束、枚举、状态、时间有效性、数据来源和质量信息。
- 建立对象运行时：对象详情、对象搜索、对象关系浏览、对象状态和来源追踪。
- 升级数据映射：支持字段预览、转换规则、主键匹配、映射测试、刷新状态和错误提示。
- 升级 Action：参数 Schema、权限检查、预演、确认、幂等、执行结果和审计信息。
- 完善工作流校验和执行日志，明确草稿、启用、停用状态。
- 增加全局 AI 助手的只读、生成草稿和 Change Set 能力。

### P1：进入业务运营阶段

- 增加真正的定时任务、事件总线、异步队列、重试、超时和人工审批节点。
- 将关键词 RAG 升级为 Embedding、向量检索、来源引用、权限过滤和增量更新。
- 建立模型与 Agent 管理：模型能力、Embedding/视觉模型、路由、成本、延迟、评测和调用追踪。
- 增加组织、角色、对象级、属性级和 Action 级权限。
- 建立完整血缘：数据源 → 本体对象 → AI 回答 → Action → 外部系统结果。
- 增加面向业务人员的对象工作台、异常处理和任务中心。

### P2：企业级平台能力

- 分支、提案、评审、合并、回滚和多环境发布。**已实现**：发布前校验、差异、活动发布保护、冻结快照和回滚均走治理服务。
- 标准化连接器、SDK、外部 API 和本体资源包导入导出。**已实现**：连接器能力/环境绑定、外部 API、可校验资源包和 Starter Kit 导入提案已接入。
- 支持地理空间、时序、媒体和实时数据。**已实现**：高级资产、记录游标、时间/bbox 查询、媒体受限存储和实时增量刷新 API/工作台已接入。
- 增加函数、优化、仿真、机器学习模型和模型反馈闭环。**已实现**：函数 allowlist 运行时、优化/仿真/时序聚合、模型运行、反馈和审计记录已接入。
- 建立零售、财务、供应链等行业 Starter Kit，但平台核心保持行业无关。**已实现**：Starter Kit 采用代码版本化、指纹校验和只生成治理提案的导入边界。

当前 P2 高级运行时的共同安全边界是：资产配置和函数配置只允许服务端声明式 allowlist，拒绝凭据、任意代码和不受控远程执行；
开发环境读取实时定义，staging/prod 读取活动发布快照。记录、运行、模型反馈和媒体元数据分别持久化并受租户/场景 ACL 保护。

## 4. 全局 AI 助手实现方案

助手放在全局 `App.vue` 中，以浮动入口打开右侧抽屉，并自动携带当前上下文：

- 当前用户、工作区、业务场景和页面。
- 当前选中的实体、关系、工作流节点和未保存内容。
- 用户有权限访问的数据、文档和本体资源。
- 当前对话附件及其解析、OCR、引用状态。

助手至少支持以下流程：

1. 根据自然语言和附件生成业务场景、本体、数据映射或工作流草稿。
2. 以 Change Set 展示新增、修改和删除内容，用户确认后再写入。
3. 对 Action 和外部系统操作提供影响范围、参数、权限和预演结果。
4. 遇到缺少信息时，用选项卡片向用户提问，并说明不同选择的影响。
5. 对回答显示数据来源、文档引用、使用的规则和调用过的工具。
6. 支持“只解释、生成草稿、应用修改、执行操作”四种明确模式。

附件分为“临时上下文”和“正式数据源”：先解析和预览，用户确认后才进入知识库或本体映射，避免未经确认污染正式数据。

## 5. 产品体验原则

- 非技术用户默认看到“业务场景、对象、任务、工作流、助手”，技术配置收纳到管理区域。
- 区分 Builder 模式和 Operator 模式：建模人员负责配置，业务人员负责使用。
- 所有修改都有草稿、差异预览、撤销和发布状态。
- 所有有副作用的操作都必须经过权限检查和明确确认。
- Agent 不直接修改数据库，统一通过类型化的本体 Action 执行。
- AI 输出必须标明来源、置信度和不确定项，不把推测伪装成业务事实。
- 保持流式反馈、可见焦点、键盘可操作和清晰的错误恢复路径。

## 6. 首个可验收闭环

优先选择一个通用的“对象—规则—动作—审批—结果”场景，完成以下验收：

- 用户用业务描述和文件附件创建场景。
- AI 生成实体、关系、属性和数据映射草稿。
- 用户可以查看差异并确认保存。
- 系统可以浏览真实对象及其来源和关系。
- 用户可以用自然语言查询对象，并获得可引用的依据。
- 用户可以通过审批执行一个类型化 Action。
- 系统记录用户、Agent、模型、数据、权限、参数和执行结果。

首要任务不是复制 Palantir 的全部功能，而是先把上述闭环做稳定，再逐步扩展连接器、行业能力和企业治理能力。
