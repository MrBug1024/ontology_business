R3 修复时延范围补充：真实 v32 的第三次输出达到 20,000 token 上限，修复异常进入外层完整编译重试，已有可校验候选被迫重做。对修复阶段明确的结构错误/截断，保留上一次经过校验的候选及阻塞项，在原两次修复预算内结束并记录未完成原因；任务预算、lease 和网络异常仍传递到持久任务边界。禁止截断 JSON 后解析、消除阻塞或增加调用预算。

R3 受信函数依赖上下文补充：平台已有激活的 Catalog 语义映射，但编译目录不提供映射身份与可读本体字段，模型只能猜 ID 或生成无绑定函数。函数建设提示须通过现有场景授权服务读取有界的激活映射及可读属性，供静态 Provider 配置引用；不提供物理字段、连接、数据行或隐式运行数据。不改变 Provider 或 Invocation 权限边界。

R3 错误归属呈现：纯粹的候选结构/引用/属性覆盖校验失败应显示“修正定义”，而非“业务关键歧义”或“副作用风险”。复用质量模块的确定性错误分类，只调整原因及展示，保持阻塞和晋级门禁；真实来源缺失与业务冲突仍走原澄清流程。
