# 医保违规审计测试问题记录

## P0：内置医保审计 Provider 无法通过业务界面启用

- **发现时间**：2026-08-31
- **复现路径**：以业务专家身份新建“医保违规审计”场景，尝试仅通过“场景能力”“智能业务顾问”和“函数”页面配置内置医保审计能力。
- **实际结果**：平台后端已内置 `trusted.medical-audit` Provider，但其启用条件不能在前端完成：Provider 需要场景命名空间为 `medical_audit`，或创建 `runtime_kind=provider` 的函数并填写 Provider key、版本、数据输入端口和映射 ID。常规新建场景页面不暴露命名空间；函数页面只提供契约、加权评分、阈值、地理距离、时序聚合等运行方式；智能业务顾问的完整建模也只会生成 `contract` 函数。前端没有 Provider 配置入口。
- **业务影响**：业务人员无法在“不改代码”的约束下启用规则命中后的确定性医保审计执行器，因此无法把规则表中的医保审计规则可靠地绑定为可重复执行的审计能力。只能退回通用 Agent 的临时 SQL/推理路径，不能满足规则引擎化、可治理复用的目标。
- **实际验证证据**：已在验证中心创建并启动“医保违规审计验证 Agent”。在绑定当前场景和已启用大模型、选择“当前全部”授权后，Agent 对话返回能力目录 `[]`，并明确提示“当前能力目录为空”“无法执行医保违规审计验证任务”。场景页面的“能力输入”页也显示“当前场景尚未声明能力输入”，而该页没有独立新增入口，只能依附于已存在的可执行能力。
- **对本次验收的直接影响**：以下三项需求分别可由内置 Provider 的 `charge_threshold`、`included_service_duplicate`、`daily_overstay` 策略覆盖：①“贵阳泰康乐综合医院刮痧治疗收费大于两次”；②“开展电子结肠镜检查，重复收取电子乙状结肠镜检查费用”；③“护理费收费超住院天数”。但这些策略必须通过 Provider 绑定到收费明细、就诊和正式数据映射后才会出现在 Agent 工具目录中。当前 Agent 的“业务能力 0 项 / 可执行 0”，因此无法在对话中对任一需求产生可核验的审计结果。
- **替代路径核验**：操作页的 SQL 查询需要预先接入关系型数据源，不能直接查询建模资料中的 Excel；可选受管技能只有 CSV/TSV 描述性分析和 OCR，均不能对三张 Excel 进行规则匹配、跨表关联与审计结果模板输出。工作流、规则、模板也没有补齐 Provider 运行绑定的入口。
- **判定依据**：前端页面实际操作与 `backend/app/providers/medical_audit/provider.py` 的 Provider 前置条件、`backend/app/services/function_definition_service.py` 的函数运行时约束一致；无可用 UI 能填写相应配置。
- **建议修复**：在场景创建或场景设置中暴露受控 Provider/命名空间选择，并在函数配置中增加受信 Provider 运行时类型及参数表单；同时校验所选输入端口、对象 API 名称和映射的兼容性后再允许保存。
