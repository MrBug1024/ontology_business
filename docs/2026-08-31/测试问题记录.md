# 医保违规审计平台测试问题记录

测试日期：2026-08-31  
测试角色：医保基金监管业务专家（全程通过平台前端操作，未修改平台代码）  
业务场景：医保违规审计（场景 ID：`0d320080d77b4b0ab3e19951fbf0c6dc`）  
验证 Agent：医保违规审计专家（Agent ID：`8d6c6f1c0cdc45728f0131ffdab876a9`）

仅记录已稳定复现、直接阻断“上传真实业务数据 -> Agent 执行审计 -> 返回模板化结果”闭环的问题。

## P0：三张事实表均无法进入 Agent 运行上下文，真实审计无法执行

### 复现步骤

1. 在验证中心打开“医保违规审计专家”。
2. 通过“上传本次对话附件”上传真实事实数据文件。
3. 分别尝试上传结算表、就诊表和项目明细表。

### 实际结果

- `结算表.xlsx` 为 63,005,935 字节，超过平台 50 MiB 单文件上限，无法上传。
- `项目明细表.xlsx` 为 247,115,103 字节，超过平台 50 MiB 单文件上限，无法上传。
- `就诊表.xlsx` 为 49,789,231 字节，压缩文件大小未超过 50 MiB，但上传解析时报错：`Office 文件展开后超过安全限制`，仍无法进入对话。
- 创建 Agent 时只允许配置业务数据库，当前界面仅提供 PostgreSQL 连接；没有可供业务专家直接使用的大型 Excel 导入、分片上传或运行数据文件桶方案。

### 期望结果

平台应至少提供一种无代码的正式运行数据接入方式，使现有三张 Excel 事实表可以完整进入同一次 Agent 审计会话，例如大文件/分片上传、受治理的运行数据文件桶，或前端可完成的 Excel 入库能力。

### 业务影响

结算表、就诊表、项目明细表缺一不可。当前限制导致 Agent 无法按就诊 ID、结算 ID 完成关联，也就无法产生任何真实违规记录或 63 列审计结果。该问题直接阻断核心业务闭环。

## P0：验证中心无法读取已就绪附件，规则匹配与模板输出同时被阻断

### 复现步骤

1. 在 Agent 对话中成功上传 `规则表.xlsx`（102.6 KB）和 `医保违规审计结果模板.xlsx`（10.9 KB），页面均显示“已就绪”。
2. 输入审计需求：“筛查七叶皂苷注射液医保支付超过 10 天的违规记录”。
3. Agent 自动选择已启用且通过结构校验的“医保违规审计执行流程”。
4. 再发送一条隔离验证消息，明确要求不调用工作流、函数或规则，只直接读取规则表附件。

### 实际结果

- 自动调用工作流时，附件绑定失败，错误码为 `CAPABILITY_DOES_NOT_ACCEPT_ATTACHMENTS`，错误信息为：`The selected capability has no file input port for the user's attachments`。
- 明确禁止调用能力、要求直接读取附件时，运行时直接报错：`'CapabilityAgentRuntime' object has no attribute 'data_sources'`。
- Agent 因此无法读取已经显示“已就绪”的规则表，也无法准确返回规则序号、国家问题清单、有关依据和违规类型；结果模板同样无法被运行时使用。

### 期望结果

对话中已就绪的附件应能被 Agent 直接读取；当 Agent 选择某个能力时，平台应只在能力声明了文件端口时进行附件绑定，或保留附件作为 Agent 上下文供模型读取。AI 生成并校验通过的工作流若需要附件，也应同时生成可用的文件输入端口。

### 业务影响

即使不考虑三张大型事实表，最小可行链路“读取规则表 -> 匹配规则 -> 读取结果模板”也无法完成。该问题使 Agent 对话无法执行规则驱动审计，是独立于大文件限制的第二个核心阻断。

## P1：智能建模产物全部不可晋级，修正任务又因模型服务不可用而失败

### 复现步骤

1. 在“医保违规审计”场景中打开智能业务顾问，提交完整建模要求。
2. 首轮生成后检查候选评审和正式写入结果。
3. 将规则表和结果模板作为临时附件加入顾问，再提交关系基数、字段引用、函数与工作流约束的修正要求。

### 实际结果

- 首轮生成产生 159 个候选，但正式写入为 0，候选评审全部显示“不可晋级”；同时出现重复标题属性、关系基数错误、未定义字段引用、工作流分支/资源引用不完整等结构性阻塞。
- 第二轮修正立即返回“模型服务当前不可用”，仅保留停用占位草稿，正式写入仍为 0。
- 最终只能由业务专家在前端逐项手工创建 8 个对象类型、11 条关系、1 个函数、2 条规则，并重新使用工作流页面的 AI 生成功能完成可校验流程。

### 期望结果

智能建模至少应产出可逐项修正和晋级的候选；对已经明确给出的主键、关系基数、字段与流程约束，不应生成全量不可晋级结果。模型服务失败时应提供可恢复重试，并保留用户已补充的修正上下文。

### 业务影响

平台宣传的核心无代码智能建模路径在该真实场景中不可用，业务专家必须手工重建全部正式模型，工作量和出错风险显著增加。该问题虽可通过大量手工操作绕过，但严重影响场景落地效率。
