# 插件开发任务：纠正后的需求与验收

本次用户要求真实的场景插件 AI 编码工作区。之前以能力版本表为开发首页的实现不满足此要求。本文只记录本次范围，不代替代码和实测证据。

| ID | 原文目标 | 可观察验收 | 影响范围 | 保持不变 |
|---|---|---|---|---|
| PC1 | 像 Codex 一样按任务开发 | 首页直接选择场景、固定能力版本、模型并输入需求；显示真实开发任务，不展示能力管理表 | 开发首页、任务 API、启动组件 | 场景管理与人工版本管理仍在原入口 |
| PC2 | AI 知道场景有什么能力 | 服务端读取同一能力目录的完整输入、输出、确认和幂等契约，页面可查看，编码上下文包含这些契约 | 编码上下文服务、DTO、能力面板 | 租户、ACL、统一 Invoker、固定版本 |
| PC3 | 可定制插件并持续纠正 | 实际模型生成多个 Skill、调用脚本、示例和参考资料；持久文件变化、差异、停止与修正；校验失败触发有界修复，耗尽后明确报告 | 源文件策略、模型 worker、编辑器 | 受信适配器只读；模型代码不在平台任意执行；lease/CAS |
| PC4 | 完成开发后发布和安装 | 编码不先要求人工填写验收回执；定版必须补齐所选能力的三类业务验收和代码审阅；发布中心选择不可变插件，安装格式验证 | 定版 API、验收组件、发布交接 | 人工验收、旧安装包内容与 hash、凭据不入包 |

影响图：插件开发任务入口 -> 完整能力契约 / 编码用例 -> 现有 AssistantThread + 受 fencing 保护的 worker -> 候选源文件 / 确定性校验 -> 人工业务验收与代码审阅 -> 不可变插件 -> 发布中心 -> 安装客户端 -> 原统一执行。

非目标：通用 OS shell 或任意租户代码在平台执行；自动发布到外部市场；改写已有工件；移除已有稳定后台 REST 协议；修复无关本体与业务顾问问题。首个安装目标沿用现有 Claude Code 插件格式，不能宣称所有宿主均可安装。

验证：候选启动无需回执、定版拒绝缺失/异版本证据、动态文件路径与源代码拒绝边界、自动修复与失效轮次、旧工件兼容；前后端测试与构建；真实数据库和浏览器启动/修正/审阅/窄屏/安装检查。未执行项在交付中说明。

必要消费者补充：真实模型交付暴露出“输入 Schema 正确但调用遗漏必需幂等键、误写回执字段”的缺口。因此编码契约加入受信 MCP 客户端的真实工具签名和回执 Schema，新任务检查调用关键字与幂等参数。旧不可变工件保留原校验语义；新审阅工件保存本次客户端契约。

## 实际验收结果

- 真实账户的合成“服务申请分流”场景，使用 Rhmax 的原生工具调用生成五个完整文件：README、两个 Skill、异步调用脚本和可校验示例。初始 JSONL 轮次确实失败；改为原生工具后，服务端反馈触发两次自动修复，修复无界轮询和 Python 换行语法错误。后续真实模型修正必需幂等参数和回执标识。
- 人工审阅进一步修正编造的环境变量、必填优先级默认值、未声明的业务结果字段及不存在的脚本入口。新契约提供真实客户端签名、回执 Schema 和环境配置名称；结构检查不能替代业务审阅，也不能据此宣称首轮生成质量达标。
- 浏览器验证开发启动无需案例表单；定版要求三个不同、同发布版本的完成回执及明确代码审阅。选择已核对的成功、加急分流边界和缺必填字段失败案例后，定版 v1.1.0，发布中心正确选中这个版本。高频案例同一秒内发生，选项增加毫秒以避免不可区分。
- 当前工作台刷新后保留源文件和已定版状态；浏览器前进/后退、390px 宽度的任务首页、工作台文件面板和发布中心通过检查，页面没有横向溢出。截图：`plugin-task-home-2026-10-05.png`、`plugin-task-coding-2026-10-05.png` 及三个 `*-narrow-*` 文件。
- `python -m pytest backend/tests -q -p no:cacheprovider`：364 passed；`npm --prefix frontend test`：260 passed；`npm --prefix frontend run build`：通过。使用 Python 3.12；既有弃用和大包警告未在本次范围中修改。
- `verify_plugin_coding_postgresql.py`：隔离真实 PostgreSQL 验证持久文件、并发创建、worker fencing、陈旧编辑拒绝、停止、版本不可变、权限与会话读取；该脚本的模型和验收数据为 synthetic，结果在 `plugin-task-postgresql-2026-10-05.json`，不冒充真实 AI 或业务质量验收。
- `verify_plugin_publication_readonly.py`：新工件哈希一致、历史版本保持不变、错误哈希/外租户/匿名读取拒绝。发布页点击两个下载入口显示生成成功；浏览器工具未捕获 Blob 下载事件，实际安装检查使用同一下载服务、同一不可变哈希的工件，数据库保持只读。详见 `plugin-task-publication-2026-10-05.json`。
- Claude Code 2.1.208 对真实 v1.1.0 插件和 Marketplace `plugin validate --strict` 通过。在任务专用 `CLAUDE_CONFIG_DIR` 下完成 marketplace add、plugin install、plugin list，显示 v1.1.0 enabled；受信适配器实际 stdio 初始化并发现五个 MCP 工具。详见 `plugin-task-installation-2026-10-05.json`。

限制：首个受支持安装宿主为 Claude Code。本轮未创建外部凭据、未在外部宿主完成带凭据的业务调用、未上传外部 Git 仓库或市场；安装成功不等于这些检查已经通过。场景当前版本未声明业务结果子字段，工作台和插件明确暴露此缺口并保留实际结构，不让 AI 自行编造字段。更广泛的业务蒸馏/顾问交付完整性问题不在本次页面纠正中宣称完成。
