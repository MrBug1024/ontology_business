# 进度、变化与组合管理

每次比较第三方提供的同一项目基线与当前实际证据；没有上次快照就不声称“比上周提升”。为每项区分：计划目标、责任人自报、已验证结果、未知、风险和待确认决策。

日期已过但没有完成证据时，写“计划日期已过，实际状态待核实”，不能直接断定延期或已完成。只有明确实际状态或负责人确认，才判断已发生偏差。新检查时间由项目策略或责任人给出，不能自行添加日期。

多人同名用稳定 ID 区分。共享同一人员仅表示潜在冲突；必须结合时间窗口、已承诺工作量和可用性判断实际冲突。未提供阶段时，不从“80%”猜成开发收尾，也不从“无更新”猜成尚未开发。

变更分析记录提出者、原基线、变化内容、原因及证据，分别检查范围、用户价值、验收、技术、测试、数据/权限、工期/成本和外部承诺的影响。未知影响请求对应负责人评估，输出候选方案及取舍。旧计划保持有效或暂停应由项目策略和授权决定确认，模型不能自行决定。不同变更不要共用一个不明确的“同意”。

组合管理逐项目隔离上下文，先形成各项目问题和可执行请求，再识别跨项目依赖与潜在资源冲突。总数从条目计算，不能在摘要中重新估算。未经输入提供，不给项目排序、预算、阶段或时间承诺。

跟踪是第三方调度器重复提供新快照并调用能力。模型说“我会持续关注”不创建定时任务；输出拟跟进事项及建议触发条件，由第三方注册任务后返回执行回执，才可告诉群成员已安排。
