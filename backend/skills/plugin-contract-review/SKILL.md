# 插件契约审阅方法

本包是受信的审阅方法说明，不运行插件或任意脚本，不授予业务调用、发布或外部副作用权限。

1. 确认插件针对明确的不可变场景发布，能力类型和稳定标识都属于当前项目选定范围。
2. 核对 Skill 元数据与目录命名、触发描述、参数收集、能力覆盖、示例和 README 的一致性。
3. 对照完整输入和输出 Schema，检查嵌套结构、必填项、默认值、约束和未知结果；禁止猜测未定义字段。
4. 核对实际客户端签名、invocation_id 回执、异步等待、预演确认、幂等键及重试语义。
5. 使用项目检索与服务端确定性检查定位问题。源码只是候选，不把静态通过称作实际业务成功。
6. 核对插件没有密钥、客户资料、连接 URL、MCP 资源 URI、任意执行逻辑或复制的平台业务算法。
7. 列出已通过检查、未覆盖行为和人工业务验收要求；只有人工定版与发布回执证明插件版本正式可安装。

用 scenario_blueprint 对照目标、本体、选中能力和依赖；不把业务蒸馏候选、对象图、事件或未选能力当作已安装的业务工具。受保护画像由服务端生成，候选源码不能覆盖。

按 delivery_profile 分开核对 Agent Skills 格式、Claude Code 安装布局、MCP 工具协议与平台交付限制。禁 hooks、动态 shell、预授权业务写入是本平台规则，不能冒称外部标准一律禁止；当前包不承诺其他宿主可用。版本使用 metadata.version 字符串。权限名称为 capability:read 和 capability:invoke。

工作流的 output.result 是执行过程；在声明输出节点中查成功且通过 contract_validation 的步骤结果。缺少输出契约时保留真实结构；不能假设每次 succeeded 都有 end 业务结果。明确处理等待、审批、拒绝、失败、取消、超时和 indeterminate，审批回复须用实际 advertised reply_texts，不能擅自批准。
