# 场景插件编程方法

本包只提供编程方法，不执行脚本，不携带客户数据，也不证明插件已验收或发布。

1. 阅读用户本轮目标、固定发布的场景画像和能力契约，明确资料理解、蒸馏候选、本体语义、能力执行与插件交付的贡献。建立目标、所选能力、输入输出、入口技能、客户端脚本与验收检查之间的对应关系；缺少来源记录时不猜测资料已冻结。
2. 先检查项目目录与既有源码，按明确需求检索文件；保留已经正确的代码，避免无关修改。
3. 基于输入 Schema 收集本次参数，说明缺少信息时如何询问。示例使用明确合成值，真实客户输入与 MCP 参考正文不得写入插件。
4. 业务执行只使用受信场景客户端的真实工具签名。保留服务端权限、预演、确认、幂等和回执协议；客户端不复制业务算法。
5. 交付有明确触发条件的 Skill、可用客户端源码和使用说明。候选源码作为文本编写，不执行命令、代码或包内脚本。
6. 主动运行服务端确定性项目校验，依据具体错误修复，并向用户提供变更、检查结果、剩余业务验收和人工发布步骤。

按 scenario_blueprint 理解冻结场景，按 delivery_profile 区分 Agent Skills 格式、Claude Code 宿主、MCP 协议与平台限制。当前安装包只支持 Claude Code；本体、事件和未选能力不是插件调用入口。编码 AI 的技能和只读 MCP 资料不自动成为插件依赖。

新项目的 references/scenario-blueprint.json 由服务端生成，只读参考不能作为候选文件改写。场景凭据需要 capability:read 和 capability:invoke 权限。工作流回执 output.result 是执行过程；依据声明的 output_node_keys，读取成功且 contract_validation=passed 的步骤结果，不猜测平铺字段或把入队当业务完成。

项目校验通过只证明检查覆盖的静态结构。编程工具和只读 MCP 的回执不能证明业务执行、副作用、业务验收或发布。
