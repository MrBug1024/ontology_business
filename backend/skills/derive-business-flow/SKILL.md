# 业务流程推导方法

本 Skill 是供 AI 使用的方法说明，不是业务事实、资料来源或执行脚本。它帮助模型把已读取并可引用的结果、过程记录和专家陈述组织成现状流程与目标流程候选。

## 输入前提

- 先确定一个真实业务结果、服务对象和需要支持的决策或行动。
- 每个现状节点至少应有可引用的过程记录、业务资料或专家陈述；只有字段、菜单、表名或最终状态时，节点必须标为假设。
- 需要调查资料时，只使用当前会话已授权的平台工具和其返回的有界结果。Skill 不读取路径、URL、数据库或凭据，也不执行包内或外部脚本。

## 方法步骤

1. 描述结果的触发条件、输入、责任角色、处理规则、输出和异常，而不是罗列页面或表。
2. 沿一条结果链逐步核对正常、失败/返工和边界情况；把事实、推断、假设和冲突分开记录。
3. 当涉及资料结构或关系时，先使用 `discover_data_landscape` 获取受管范围内的候选，再按需要使用 `compare_database_samples` 核对单键或复合键。样本证据只证明样本范围。
4. 形成现状流程，标注每个节点的依据、覆盖范围和未决问题。缺少过程证据时，不把低效、固定分工或损失写成事实。
5. 基于已确认痛点提出目标流程候选，说明删除、合并、替代或保留每个节点的理由、风险和衡量方法。目标流程是建议，不是已授权变更。
6. 通过 `ask_human` 询问阻断性歧义，每次最多三问；信息不足时停止推导，不用完整草图掩盖缺口。

## 输出结构

返回或提交阶段建议时，优先包含：

- `value`: 结果、受益者、决策/行动和成功标准；
- `as_is`: 现状节点、触发、输入、规则、输出、异常及证据引用；
- `to_be`: 目标节点、改动理由、预期衡量和风险；
- `assumptions` / `conflicts` / `open_questions`: 尚未核实的边界；
- `limitations`: 样本范围、资料缺失和不能由当前证据证明的内容。

不得把建议写入正式业务模型、自动改变人工决策、执行外部副作用或声称发布成功。只有平台受信工具的回执能证明工具调用；只有人工采用和正式发布回执能证明阶段产物生效。
