# 业务能力蒸馏方法

本 Skill 是 AI 的受信方法包，用于把已经调查的业务认知整理成候选能力契约。它不携带客户数据，不提供业务事实，不执行命令，也不代替平台的确定性校验、人工采用和正式发布。

## 输入前提

- 已确认能力服务的对象、受益者、核心结果、边界和成功标准，或明确标为候选/待确认。
- 已有可追溯证据支持输入、流程、规则、输出和异常；每条结论区分 `fact`、`inference`、`hypothesis` 和 `conflict`。
- 业务数据只来自本次显式提供或平台受管工具读取的资料。Skill、MCP、工具定义、模型提示词和内部运行回执是能力，不是业务资料。

## 方法步骤

1. 从一个高价值结果开始，定义最小闭环：触发、业务输入、必要上下文、处理步骤、规则/人工判断、结构化输出和失败状态。
2. 将流程中的业务对象、关系、生命周期和权限边界映射到逻辑模型；不要复制物理表、路径、连接信息或客户字段作为公共契约。
3. 为每个输入输出建立封闭、可校验的类型与约束，说明来源、是否必需、空值/边界行为和脱敏要求。
4. 为规则和决策记录版本、适用范围、证据和人工覆盖条件；低置信度判断进入待确认项，不升级为事实。
5. 检查依赖闭包、租户/角色、幂等、预演/确认、审计和错误状态；有副作用的动作必须保留服务端确认门禁。
6. 输出候选并列出限制、未决问题、质量指纹和建议验证步骤。只调用平台注册的受信工具，不执行 Skill 中的脚本或任意文本命令。

## 输出结构

提交能力候选时至少包含：

- `capability`: 稳定标识、名称、价值、范围和版本意图；
- `inputs` / `outputs`: 字段类型、约束、证据来源和边界行为；
- `workflow`: 触发、步骤、规则、异常与人工介入点；
- `objects` / `relations`: 逻辑对象和待确认基数；
- `governance`: 权限、租户、幂等、审计、确认和回滚/未知结果处理；
- `evidence` / `limitations` / `open_questions`: 逐项引用、覆盖范围和缺口。

结果只是候选或提案。不得声称已经保存、发送、执行、发布或改变业务事实；必须等待服务端校验、人工采用、正式发布以及外部执行回执。Skill 内容、MCP 元数据和调查工具说明不得写进业务 `evidence` 或普通业务资料列表。
